# ADR-001：统一正式 Web UI 入口

状态：M1 设计裁决候选，M8 才执行切换。
日期：2026-11-24

## 背景

rip-web 运行于 Vite 5173，rp_server 运行于 7800 并同时承载 API 与 M7 旧静态只读工作台。两套入口使用户难以辨认主控制台和只读工作台的角色。

## 决策

- rip-web 是唯一正式用户 UI。
- rp_server 的 API、Token、权限、只读连接和拒写策略继续保留。
- M7 的 Overview、Resources、Reviews、Tasks 只读能力迁入 rip-web 对应页面。
- 迁移期间不删除 `apps/server/static/`，也不更改 API 服务绑定。
- 只有数据对账、只读写入拒绝、Token、深链接、端到端回归和回滚演练全部通过，才在 M8 单独调整 7800 根路径的旧静态入口。
- 生产环境用同源站点/反向代理提供 rip-web 和 /api，不把 Vite 5173 当生产端口。

## 后果

用户只使用一个工作台，服务端权限仍然有效。迁移有临时双入口期，但不把 M7 静态页继续发展为第二套正式产品。

## 风险与回滚

风险：旧用户收藏 7800 根路径；独立只读验收依赖旧页面；双入口期间数据更新时序不同。回滚：保留静态文件和服务端路由，切换失败可恢复根路径旧静态 UI，不需要回滚 API。
