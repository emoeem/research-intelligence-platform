# AppShell 与面板布局规格

## 一、桌面结构

```text
┌ Sidebar ┬──────────────────────────────────────────────────────────┐
│         │ Topbar: Breadcrumb / Search / Runner / Notifications     │
│ Groups  ├──────────────────────────────────────────────────────────┤
│         │ WorkspaceNav: 当前工作区的子导航                         │
│         ├──────────────────────────────────────────────────────────┤
│         │ SessionTabs: 仅在真实多文档/编辑会话存在时显示            │
│         ├──────────────────────────────────────────┬───────────────┤
│         │ Main Workspace                           │ Inspector     │
│         │ 按页面模板使用 Content / Data / Editor   │ 按需显示       │
│         │ / Canvas / Workbench                     │ 可拖动         │
│         ├──────────────────────────────────────────┴───────────────┤
│         │ Activity Dock，默认收起，运行态显示摘要                   │
└─────────┴──────────────────────────────────────────────────────────┘
```

## 二、尺寸范围

| 区域 | 默认 | 约束 |
|---|---:|---|
| Sidebar 折叠 | 56px | 已有 56px 基线 |
| Sidebar 展开 | 224px | 不得挤压小视口主区 |
| Topbar | 52-56px | 单行，按钮对齐 |
| WorkspaceNav | 40px | 仅当前工作区 |
| Inspector | 300px | 可在 260-420px 内调整 |
| Activity Dock 收起 | 32-36px | 只显示状态/切换入口 |
| Activity Dock 展开 | 220-320px | 支持拖动高度 |

以上是设计目标值，进入 M2 前需在实际浏览器进行断点测量。

## 三、页面布局模式

- `content`: 常规页面最大宽度，适合 Settings 和说明内容。
- `dashboard`: 使用响应式网格，不强制所有卡片同尺寸。
- `data-workspace`: 主数据表占据剩余高度，不采用固定 20rem。
- `workbench`: 100% 可用宽度和高度，适合 HTTP History、Proxy。
- `editor`: 编辑器与结果区可调分栏，适合 Repeater、Decoder。
- `canvas`: 画布占据主区，工具面板按需展示。
- `immersive`: 隐藏非必要 Shell，用于大编辑器/全屏视图。

## 四、Inspector 规则

- 默认不占用列表/总览页空间；页面存在已选择对象时才建议展开。
- 不显示通用页面元数据作为主体。
- 展示当前对象的领域字段、来源、权限、关联任务/知识/证据、运行状态。
- 无对象时明确空态或完全折叠。
- 可拖动宽度，最小/最大值受限，记忆最近有效宽度。
- 小屏转为 Drawer，不将主内容压缩到不可用宽度。

## 五、Activity Dock 规则

- 默认收起。
- 收起状态可见运行任务计数和错误指示。
- 运行中只显示真实 API/SSE 状态；未知或未接入不能显示为健康。
- 展开后按任务、Tool Runs、Logs、Output、Runner Status 分类。
- 支持高度调整、键盘聚焦和关闭/折叠。
- 默认不自动弹开，不打断用户操作。

## 六、页面操作层级

全局 Topbar 只保留搜索、运行状态、通知和全局入口。页面主操作放在 PageHeader。行级操作放入 DataTable 行菜单或详情工具栏。高风险写操作保持 TrustConfirmDialog 和服务端权限校验。
