# 微信小程序接口面全流程审计流水线-静态全集-四态认证矩阵-全量路由巡

> 状态: `script_ok` — 配套脚本 `poc.sh`
> 本文件说明**为什么这么写**，不是使用手册。用法见脚本头 docstring。

## 为什么需要这个脚本

小程序和 Web 的差别：接口全集是**能从包里静态挖全**的。wxapkg 解开后，
app-service.js 里的 request({url: ...}) 调用就是全量 API 面，不需要爬、不需要猜。

## 判据设计

四态，少一态结论就不可靠：
  S1 无任何凭证        200 → 无鉴权；401 → 有拦截
  S2 过期/伪造 token   200 → 只做存在性校验（更危险）；401 → 校验签名/有效期
  S3 低权 token        能读到别人数据 = 水平越权
  S4 无 token + 伪造 Referer/X-Client → 鉴权依赖可伪造的头

## 常见误报（先排除这些，再下结论）

① 小程序路由兜底很常见：任意路径返回同一份 JSON → 必须先建随机路径基线
② S2 返回 200 有两种解释：伪造成功，或服务端"忽略 token 解析失败、当匿名处理"
   —— 用 S1 的响应比对：S1 与 S2 完全一致 = 匿名放行，不是伪造成功
③ code 字段可能是字符串 "401" 而不是数字
④ 有些接口用 HTTP 200 + body 里的 code=-1 表示未登录

## 验证与收口

结论收敛方式：
  S1=OPEN                      → 完全无鉴权，最高
  S2=OPEN 而 S1=401            → 只校验 token 存在性，不验签名
  S3=OPEN 且返回数据含他人 ID  → 水平越权
  S4=OPEN 而 S1=401            → 鉴权依赖 Referer（可伪造）
接口清单来源：wxapkg-unpack.py 解包后 grep url:，或用 chunk-harvest.py 从 web bundle 提。
