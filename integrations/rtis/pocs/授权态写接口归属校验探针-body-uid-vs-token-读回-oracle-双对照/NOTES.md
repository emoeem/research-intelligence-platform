## 已落地脚本

```
./poc.sh --base https://TARGET --token TOKEN \
  --self-uid ME --other-uid 1000 \
  --read-path /api/user/profile --read-field letterRemind \
  --write-path /api/user/setting --write-field letterRemind
```

流程：读双方基线 → 写自己（证明接口可写）→ 读回 → 写他人 → 读回 →
**无论结果如何都还原他人数据并读回确认**。

## 三条设计铁律

1. **只用可回滚的开关型字段**。不用昵称/头像/简介，不用整对象覆盖式接口
   （缺字段会被清空）。
2. **200 不等于写成功**。身份取不到时业务层会空转返回 200 但 0 行更新，
   一律以读回为准。
3. **两组对照缺一不可**。只测「写他人」不算数——还要测「写自己」，
   只有两次结果不同才能证明 uid 参与了写入决策。

## 实测（2026-11-01，本地 mock 三模式）

| mock 行为 | 判定 | 对否 |
|---|---|---|
| body uid 生效 | `CRITICAL`，附 `0 → 1` 证据，并成功还原 | ✅ |
| 按 token 解析忽略 uid | `归属校验正确` | ✅ |
| 写接口 403 | `前置不成立，本次未得出结论` | ✅ |
| token 失效 / 读不到基线 | exit 2，明确说「不要当成没有越权」 | ✅ |

## 已知局限

- other-uid 的字段必须**你自己能读到**，否则做不了读回对照
- 有 sign / 时间窗二次校验的写接口会走「不确定」分支，需换手法
- 缓存型读接口会让读回失真，必要时加 `--pause`

## 方法族: `oracle`

### 执行框架

1. 先建基线: 用一个确定不存在的输入（随机路径 / 随机 ID）取响应
2. 归一化: 抹掉每次变化的时间戳、uuid、耗时，只留结构指纹
3. 单变量对照: 每次只改一个维度，看结果在哪一维翻转
4. 分类收敛: 把结果归到有限几类（存在/不存在/需认证/被拦截）
5. 反证: 主动构造一个「应该命中」的输入，确认判据不是永远返回同一类

### 常见误报（先排除这些，再下结论）

- 软 404: 服务端对不存在的资源返回 200 + 首页，必须比 body 不比 code
- CDN 兜底: 任意路径都返回同一错误页，导致所有请求「看起来一样」
- WAF 混淆: 403 既可能是拦截也可能是资源不存在（部分网关这么实现）
- 缓存: 同一 URL 第二次返回缓存结果，掩盖了真实差异
