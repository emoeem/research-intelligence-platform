## 主题

加密信封路由器 entrance API：四码 oracle 定界白名单，枚举白名单内方法


## 背景

包网平台的 `/entrance/api` 是一个**统一入口**：所有业务方法都走同一个 URL，
用 `requestData`（加密信封）里的 `url` 字段路由到具体 handler。

```
POST /entrance/api
requestData = AES({url: "member/getInfo", params: {...}})
```

好处是攻击面集中；坏处是只要解开信封，就能**直接调用内部方法**，绕过前端路由限制。

## 四码 oracle

这是本方法的核心。服务端对不同的失败原因返回**不同的业务码**：

| code | 含义 | 推断 |
|---|---|---|
| `111034714` | 方法不存在 | url 不在路由表里 |
| `111034715` | 方法存在但未授权 | **白名单内**，但当前会话无权 |
| `111034716` | 参数错误 | **白名单内**，且已进入业务逻辑 |
| `111034717` | 签名错误 | 信封层就没过 |
| `1110xxxxx` | 其他业务错 | 已进入业务层 |

关键差异：**714 vs 715 vs 716**。
- 714 = 不在白名单
- 715 = 在白名单，被鉴权拦
- 716 = 在白名单，鉴权过了，只是参数不对

所以 716 是最有价值的信号：**它证明当前身份能调用这个方法**。

## 方法枚举策略

1. 先确认信封格式（key/iv 从 bundle 提，或用 `entrance-api` 解密脚本）
2. 用已知方法名做正样本（如 `member/getInfo`），确认 716/200
3. 用随机方法名做负样本，确认 714
4. 从 bundle 的字符串池里提取候选方法名（`grep -oE '"[a-z]+/[A-Za-z]+"'`）
5. 逐个测，只记录 715/716
6. **不要暴力枚举**：方法名是业务命名，暴力命中率接近 0，且会触发风控

## 参数类型层判据

同样返回 716，但错误详情能进一步分层：

```
{"code":111034716,"message":"uid 不能为空"}     → 方法已到达，缺必填字段
{"code":111034716,"message":"uid 类型错误"}     → 方法已到达，类型不对
{"code":111034716,"message":"未知参数 uid"}     → 方法已到达，识别了字段名
```

第三种最有价值：它说明服务端**认识这个字段名**，可以据此反推接口契约。

## 常见误报

- 715 不代表可利用 —— 它是"白名单内但无权"，需要找降级路径
- 716 不代表数据可读 —— 只代表调用被接受
- 信封签名可能要 nonce，重放会失败
