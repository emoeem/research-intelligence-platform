## 方法族: `biz`

### 执行框架

1. 梳理业务闭环: 注册 → 登录 → 充值 → 下单 → 结算，每步的接口和参数
2. 抓真实请求: 用测试账号跑完整流程，比猜字段可靠
3. 定位契约: 从 bundle/APK 里找字段名和校验规则（长度/首字母/枚举值）
4. 业务码 oracle: 逐字段改值，观察业务错误码变化，反推校验规则
5. 越权测试: 换 uid / 换 token / 换厅 ID，看数据是否串号

### 常见误报（先排除这些，再下结论）

- 业务错误码统一: 所有失败都返回同一个 code，无法用业务码做 oracle
- 前端校验冒充后端: 改了前端限制但服务端仍拒，说明校验在服务端
- 参数名猜错: 字段名是拼音/缩写/驼峰混用，必须从产物里取真实名
- 会话绑定: 某些接口把 token 和 IP/设备指纹绑定，换环境即失效
