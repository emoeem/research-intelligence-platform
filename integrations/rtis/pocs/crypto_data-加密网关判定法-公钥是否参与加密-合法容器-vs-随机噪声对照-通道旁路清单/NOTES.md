五条判据（按判别力排序）：16 字节对齐 → 跨样本去重 → 跨样本共享首块 →
定长高熵前缀（RSA 段）→ 明密文长度对齐关系（PKCS7）。

## 实测（2026-11-01，五类各造样本）

| 样本构造 | 判定 | 对否 |
|---|---|---|
| 同一明文重复加密 | `DETERMINISTIC` high | ✅ |
| CBC + 随机 IV + 明文对 | `CBC-PKCS7-RANDOM-IV` medium | ✅ |
| 256B 随机前缀 + AES 段 | `RSA-HYBRID-SUSPECTED` medium | ✅ |
| 随机 30 字节（非对齐） | `STREAM-OR-ENCODING` medium | ✅ |
| CBC 无明文对 | `AES-BLOCK-UNKNOWN` low | ✅（诚实标 low） |

## 修过的两个判据错误

1. **「固定开销 == 16」是错的**。PKCS7 开销 = `16 - len(pt) % 16`，随明文长度变。
   改成「密文长度恰为明文按 16 向上取整 + 一个整块」。
2. **RSA 前缀检测不能从小到大试**。128B 前缀只是 256B 前缀的一部分，永远先命中，
   会把 RSA-2048 误报成 RSA-1024。改正序。

## 已知局限

- 单看密文无法区分「RSA 混合」与「恰好 256+16k 长的 CBC」，所以只给 SUSPECTED
- 熵阈值 0.85 是实测出来的（256B 随机段 ≈0.90，32B AES 密文 ≈0.60），
  样本量小时会漂

## 方法族: `oracle`

### 执行框架

1. 先建基线: 用一个确定不存在的输入（随机路径 / 随机 ID）取响应
2. 归一化: 抹掉每次变化的时间戳、uuid、耗时，只留结构指纹
3. 单变量对照: 每次只改一个维度，看结果在哪一维翻转
4. 分类收敛: 把结果归到有限几类（存在/不存在/需认证/被拦截）
5. 反证: 主动构造一个「应该命中」的输入，确认判据不是永远返回同一类

### 常见误报（先排除这些，再下结论）

- 软 404: 服务端对不存在的资源返回 200 + 首页，必须比 body 不比 code
- CDN 兜底: 任意路径都返回同一错误页，导致所有请求「看起来一样」
- WAF 混淆: 403 既可能是拦截也可能是资源不存在（部分网关这么实现）
- 缓存: 同一 URL 第二次返回缓存结果，掩盖了真实差异
