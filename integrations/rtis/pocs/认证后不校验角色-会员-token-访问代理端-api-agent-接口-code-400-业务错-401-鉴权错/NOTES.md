# 认证后不校验角色-会员-token-访问代理端-api-agent-接口-code-400-业务错-401-鉴权错

> 状态: `script_ok` — 配套脚本 `poc.sh`
> 本文件说明**为什么这么写**，不是使用手册。用法见脚本头 docstring。

## 为什么需要这个脚本

系统区分"会员端 / 代理端 / 管理端"，三套前端，但后端是同一份代码。鉴权中间件只做
`if (!token) 401`，没做 `if (role != agent) 403`。拿会员 token 打代理接口，能过。

## 判据设计

关键是区分"业务错"和"鉴权错"：
  code=401 / 403            → 鉴权层拒绝（角色校验有效）
  code=400 / 参数错误 / 库存不足 → **鉴权已过**，业务层报错 → 越权成立
  code=0 / 200 + 数据        → 直接越权（更严重）
  404 / 502                  → 接口不存在（代理端可能在别的域名/端口）

## 常见误报（先排除这些，再下结论）

① **把 400 当成"被拦"是最常见的误判**。400 恰恰证明请求穿过了鉴权层
② 代理端 API 可能挂在另一个域名或端口（agent.example.com），需要先确认根
③ token 形态：JWT 要加 Bearer 前缀，裸 token 不加，配错会全 401
④ 200 但 body 是 `{"code":401}` 的情况 —— 业务码比 HTTP 码更可信

## 验证与收口

必须补的两步（否则报告会被打回）：
  1) **角色反向验证**：拿真实代理 token 打同一接口，确认正常代理返回什么。
     代理也返回 400 参数错 → 说明这接口本来就要求参数，你的 400 不构成越权证据
  2) **数据边界**：能通过的接口里挑一个 GET 取列表，看返回的是"自己名下"还是"全体"。
     返回全体 = 水平越权，比缺少角色校验严重一级
修复建议要具体：OAuth scope / 路由分组 / 中间件 requireRole('agent')，
写清在哪一层加，不要只写"加个判断"。
