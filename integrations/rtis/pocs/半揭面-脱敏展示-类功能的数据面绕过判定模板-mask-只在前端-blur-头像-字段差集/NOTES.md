# 半揭面-脱敏展示-类功能的数据面绕过判定模板-mask-只在前端-blur-头像-字段差集

> 状态: `script_ok` — 配套脚本 `poc.sh`
> 本文件说明**为什么这么写**，不是使用手册。用法见脚本头 docstring。

## 为什么需要这个脚本

看到 138****8000，要判断脱敏发生在哪一层：
  层1 前端 CSS/DOM —— DOM 里是明文，只是 blur 或替换了文本 → 读 DOM 就有
  层2 接口已打码   —— 接口返回打码值 → 脱敏在服务端，要看旁路
  层3 存储已打码   —— 库里就是打码值 → 无解
判据是**字段差集**，不是"看起来有星号"。

## 判据设计

四个差集方向：
  D1 列表 vs 详情  同一对象两处返回的 phone/idcard 是否一个明文一个打码
  D2 接口 vs 导出  导出（csv/xlsx/print）经常复用"内部视图"漏脱敏
  D3 接口 vs 搜索  模糊匹配接口常返回未脱敏的高亮片段
  D4 接口 vs 分享  分享页为 C 端展示有时给明文

## 常见误报（先排除这些，再下结论）

① 打码字符不一定是 *，还可能是 · 或 x 或全角 ＊
② 头像 blur 是图片层，不属于数据脱敏，降级处理
③ 导出接口可能返回 200 但内容是空的（无权限时返回空表而不是 403）
④ 搜索联想返回的是"匹配片段"，可能只含部分字段

## 验证与收口

DOM 层判定在浏览器里做：
  1) F12 → Elements，搜 138 或 ****
  2) DOM 是打码值 → 服务端脱敏
  3) DOM 是完整值但显示打码 → CSS blur / font-size:0 / ::after 覆盖，
     删掉 ::after 或改 filter:none 就可见
这条路径不产生数据面漏洞，报告中要与"接口泄露"分开写。
