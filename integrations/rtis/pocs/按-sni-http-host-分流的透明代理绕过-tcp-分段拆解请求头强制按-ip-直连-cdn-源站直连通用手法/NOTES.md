# 按-sni-http-host-分流的透明代理绕过-tcp-分段拆解请求头强制按-ip-直连-cdn-源站直连通用手法

> 状态: `script_ok` — 配套脚本 `sni-split-bypass.py`
> 本文件说明**为什么这么写**，不是使用手册。用法见脚本头 docstring。

## 为什么需要这个脚本

目标在 CDN 后面，直接解析到源站 IP 访问会被拒（SNI 不匹配 / Host 不在白名单）。
三种分流实现各有一种绕过：
  M1 SNI 分流（TLS 层）：对 IP 直连但 SNI 设成目标域名
  M2 Host 分流（HTTP 层）：TCP 连到 IP，发 Host: 目标域名
  M3 表头拆包检测：TCP 分段发送，握手后加密通道里发 Host

## 判据设计

关键判据不是"通"，是**四种方式的响应必须互不相同**：
  全相同 → 拦在更前面（IP 黑名单 / 全站 WAF），这条路走不通，别再试变体
  不同   → 分流存在，且部分方式可绕

## 常见误报（先排除这些，再下结论）

① 如果四种方式返回同一个 403 页面，不是"绕过失败"，是拦截在更前面
② 证书 CN 会暴露源站真实域名（比响应体更可靠）
③ M3 分段发送对 HTTP/2 无效（h2 的头部是 HPACK 压缩的，看不到明文 Host）
④ 部分 CDN 会校验 SNI 与 Host 一致，不一致直接 reset

## 验证与收口

走不通时的替代思路：
  · 找 CDN 的其他回源域名（CNAME 链、证书 SAN、DNS 历史记录）
  · 找同源站的其他 IP（C 段只扫 80/443 + 只比 favicon，不扫全端口）
  · 被动 DNS / 证书透明日志（crt.sh）找历史解析
走通时：直接对 IP 做 vhost 枚举，并检查源站是否开放了 CDN 上没有的端口。
