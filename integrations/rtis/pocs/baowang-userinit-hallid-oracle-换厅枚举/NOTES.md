# baowang-userinit-hallid-oracle-换厅枚举

> 状态: `notes_only` — 目标/业务特定，通用脚本会失真。
> 本文件记录**真实技术细节与判定框架**，不是脚本。

## 主题

包网（白牌博彩）会员初始化接口：用 hallId 换厅枚举


## 背景

包网平台的会员初始化接口（`/api/user/init`、`/api/member/userinit`、
`/infe/rest/user/init.json` 一类）会返回当前账号可见的"厅"（hall / 场馆 / 游戏分区）
列表。请求参数里通常有 `hallId` / `hall_id` / `siteId`，某些实现**不校验该 hall 是否属于
当前会员的代理线**，于是可以枚举出平台下的全部厅。

## oracle 设计

关键：**不能靠"有没有数据"判断**，要靠业务码的稳定差异。

| 返回值 | 含义 |
|---|---|
| `code=0` + 非空 halls | hall 存在且被分配 |
| `code=0` + 空 halls | hall 存在但本账号无权（或确实没有厅） |
| `code=1101` / `hall not found` | hall 不存在 |
| `code=500` | 参数校验失败（hallId 类型不对） |
| HTTP 200 + HTML | 打到了前端路由，接口路径错 |

只有前两类的差异才构成 oracle。第三、四类是噪音。

## 枚举策略

1. **先定边界**：hallId 通常是递增整数。用二分找上界（`hallId=1` 能过、
   `hallId=999999` 报"不存在"），再在线性区间内小步长采样
2. **不要全量扫**：命中 10 个厅就够证明"跨代理线可见"，再扫就是扫描行为
3. **单变量**：只改 hallId，其余参数（token、版本号、设备号）固定
4. **限速**：0.5s 以上，这类接口常挂在风控后面

## 常见误报

- 前端切换厅时带了新 token —— 那是正常的多厅账号，不是越权
- 返回的 halls 全是 null / 空对象 —— 探到了 hall 但没数据
- 不同 hallId 返回同一个 body —— 参数根本没被使用（很多接口的 hallId 是装饰性的）

## 判据收口

真越权必须满足：**同一 token + 不同 hallId + 返回的厅列表确实不同 + 列表里的厅
不属于该 token 的代理线**。前三条容易测，第四条需要知道代理线归属（从
`/api/agent/info` 或账号注册来源推断）。

- [ ] 建基线：hallId=1 与 hallId=999999 的响应差异

## 为什么没有可执行脚本

这类条目的价值在「**针对特定目标的具体契约**」：错误码表、字段名、加密常量、
路由命名。把这些抽象成"通用脚本"，产出的就是一个装满占位符的空壳，
反而比这份说明更容易误导人。

- `../crypto_data-加密网关判定法-*/crypto-gateway-probe.py`（判定加密形态）

- `../appid-secret-泄露面静态扫描-*/scan-appsecret.py`（批量扫凭证）
- `../webpack-chunk-map-提全量按需-chunk-含-hash-批量抓取/chunk-harvest.py`（抓全量 bundle）
