# 世纪佳缘-花千树-_t-签名离线伪造-cpi.jiayuan.com-fam-未授权访问

> 状态: `notes_only` — 目标/业务特定，通用脚本会失真。
> 本文件记录**真实技术细节与判定框架**，不是脚本。

## 主题

世纪佳缘花千树：`_t` 签名离线伪造与 fam 接口未授权访问


## 背景

`cpi.jiayuan.com` 的若干接口带 `_t` 参数（时间戳型签名）与 `fam` 头。签名算法在
前端 bundle 里，参数固定时可离线复现，从而绕过"必须从 App 发起"的限制。

## 签名还原步骤

1. **定位签名函数**：在 bundle 里搜 `_t`、`sign`、`timestamp`，找拼接顺序
   常见形态：`_t = md5(param1 + param2 + secret + ts)` 或
   `_t = hmac_sha1(sortedQuery, secret) + "." + ts`
2. **确认参与签名的字段**：用**单变量法**——固定其他参数，只改一个，看 `_t`
   是否变化。变的才参与签名
3. **确认时间窗口**：伪造的 `_t` 有效期通常是 ts ± 300s，超出则报"签名过期"
4. **确认是否需要 nonce**：若服务端记 nonce，重放会失败

## 关键判据（区分三种"看起来成功"）

| 现象 | 含义 |
|---|---|
| 200 + 正常业务数据 | 签名伪造成功，且接口无鉴权 |
| 200 + `{"code":"签名错误"}` | 签名算法还原错了 |
| 200 + `{"code":"用户未登录"}` | **签名对了**，但缺 token → 签名绕过成立，只差鉴权 |
| 401 + 空 body | 网关层拦，签名没到业务层 |

第三种最容易被忽略：它证明签名这一层已经过了，只是还差登录态。

## fam 头

`fam` 在部分实现里是"来源标识"（如 `fam=app`、`fam=h5`），服务端据此决定走哪套
鉴权。把 `fam` 从 `app` 改成别的值有时能跳过 token 校验 —— 这是**降级鉴权**。

## 未授权访问的收口

签名绕过 + 无鉴权 = 可直接读数据。但要注意：
- 这类接口返回的往往是"用户自己的"数据，需要 `uid` 参数才能读到别人的
  → 找到 uid 参数后测水平越权
- 若 uid 是自增整数，先测 ±1 的相邻值，不要批量遍历
