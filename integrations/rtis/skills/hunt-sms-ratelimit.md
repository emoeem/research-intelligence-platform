# 短信轰炸与频控缺口

## 一、触发面（发验证码的接口不止"登录"）

登录/注册 · 密码找回 · 手机换绑 · 实名认证重发 · 支付验证 · 营销短信订阅 · 客服回电（语音轰炸同构）。**重发倒计时只在前端**的场景（刷新页面重发）是最低门槛的命中点。

## 二、频控绕过矩阵（六种，按命中率排）

| 绕过 | 手法 |
|---|---|
| 格式绕过 | 手机号变形：`+8613800000000` / `086-138...` / 空格 `%20138...` / 全角数字 / `1380000000016`（超长截断）——后端归一化缺失时每种格式独立计数 |
| 换参名 | `phone` → `mobile`/`tel`/`userPhone` 参数污染（`phone=a&mobile=b` 双参数） |
| 接口复用 | A 业务频控严、B 业务频控松但打同一短信通道（注册 vs 找回） |
| 并发竞态 | 同一请求 50 并发齐发（Turbo Intruder/race 模板），频控是"先查后写"无锁时穿透（衔接 hunt-race-condition） |
| IP 维度绕过 | X-Forwarded-For 伪造（频控按 XFF 计数时）+ 代理池（衔接 cn-proxy-pool） |
| 前端校验 | 图形验证码校验在另一个接口、发短信接口不校验 token（衔接 hunt-captcha-bypass） |

## 三、判定与危害证明纪律

- 证明口径：**自备测试手机号（自己名下），连续触发 3-5 条即停**，截图运营商收件记录
- 绝不轰炸他人号码：不给第三方手机号发任何一条；证明"可遍历号码"用**同一测试号×多格式**而不是换目标号
- 定级锚点：无任何频控（格式绕过全通）= 中危偏上；叠加竞态穿透 = 高于普通频控缺口；纯前端倒计时 = 中危下沿
- 关联升级链（命中后顺势测）：
  1. 验证码回显在响应 → 任意用户登录（高危）
  2. 4 位纯数字验证码 + 无尝试限制 → 爆破接管（高危，衔接 hunt-captcha-bypass 的爆破纪律）
  3. 找回接口验证码逻辑缺陷 → 任意账号接管（严重）

## 四、报告话术要点（SRC 特色）

- 危害写"短信成本攻击（每次 ¥0.0x × N 条）+ 扰动真实用户 + 可能引发通道封禁（殃及业务）"
- 附：绕过矩阵命中的具体格式列表、测试号收件截图（打码）、频控维度缺失分析（手机号/IP/设备/验证码前置四维逐个标注）
- 回填：category=other（或 business-logic 对应物），tags 带 sms/频控/轰炸，usage 记"触发面→绕过格式→证明口径"
